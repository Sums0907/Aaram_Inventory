# Packer Webhook API Contract

This document describes the API contract and data payload for the physical events transmitted from the **Aaram Packer App** to the **AaramBooks Inventory Truth Engine**.

Currently, this contract handles the **forward fulfillment (PACKED)** event.

## Core Architectural Principle
> **The Aaram Packer App is the authoritative source of truth for physical dispatch.** When a packer physically packs an order and marks it as packed, a webhook is fired to AaramBooks. AaramBooks trusts this event to generate the corresponding physical outbound inventory movements (`SALES_FULFILLMENT`).

## Webhook Endpoint

**POST** `/api/v1/internal/webhooks/packer/events`

## Payload Schema (`PackerEventPayload`)

The payload schema is defined in [`src/domains/inventory/schemas/packer_webhook.py`](../src/domains/inventory/schemas/packer_webhook.py).

```json
{
  "event_id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "event_type": "PACKED",
  "occurred_at": "2026-08-17T10:30:00Z",
  "order_id": "SHOPDECK-ORD-999",
  "awb": "FORWARD-AWB-123",
  "items": [
    {
      "sku": "SKU-ABC",
      "quantity": 1
    }
  ]
}
```

### Field Definitions

| Field | Type | Description |
|---|---|---|
| `event_id` | `UUID4` | Unique, immutable identifier for the physical event generated by the Packer App. Used by AaramBooks to guarantee idempotency. |
| `event_type` | `str` | The type of physical event. Currently, only **`PACKED`** is supported. |
| `occurred_at` | `datetime` | The exact UTC timestamp when the physical event occurred in the warehouse. |
| `order_id` | `str` | The external business identity of the order (e.g., ShopDeck Order ID). |
| `awb` | `str` | The logistics tracking number (AWB) associated with the dispatch. |
| `items` | `List[PackerEventItem]` | The array of SKUs and quantities that were physically packed into the box. |

### Item Definition (`PackerEventItem`)

| Field | Type | Description |
|---|---|---|
| `sku` | `str` | The exact SKU code that was packed. |
| `quantity` | `int` | The physical quantity packed. Must be greater than 0. |

## Webhook Reliability & Delivery Rules

1. **Idempotency:** AaramBooks relies on the `event_id` to ensure that duplicate webhook deliveries do not result in duplicate inventory deductions. If AaramBooks has already successfully processed `event_id`, subsequent requests with the same ID will return a successful 200 response without altering inventory.
2. **Immutability:** Once a `PACKED` event is successfully transmitted to AaramBooks, it cannot be modified. Any subsequent adjustments or corrections must be handled via separate inventory adjustment workflows, not by re-sending a modified webhook.
3. **Future Extension:** This payload structure is designed to be easily extensible. In the future, the `event_type` field will be expanded to accept return events (`RTO_RECEIVED` and `CUSTOMER_RETURN_RECEIVED`) utilizing the same fundamental data contract.
